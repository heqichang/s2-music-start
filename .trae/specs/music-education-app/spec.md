# 音乐启蒙教育软件 - 产品需求文档

## Overview
- **Summary**: 一款面向 7-12 岁儿童的 Web 端音乐启蒙教育软件，通过游戏化互动培养用户的音乐感知能力，建立对音高、节奏、音色、力度四大音乐基本要素的直观认知。
- **Purpose**: 让儿童在趣味游戏中潜移默化地建立音乐感知基础，降低音乐学习的门槛，激发对音乐的兴趣。
- **Target Users**: 7-12 岁小学生，无音乐基础或初学阶段的儿童，可独立或在家长陪同下使用。

## Goals
- 通过"高低音辨别"游戏，训练用户对音高的敏感度和判断力
- 通过"节奏模仿"游戏，培养用户的节奏感和节拍精准度
- 通过"乐器猜猜看"游戏，帮助用户识别不同乐器的音色特征
- 通过"强弱探索"可视化互动，让用户直观理解音乐力度（f/p）的概念
- 通过"虚拟乐器"自由探索模式，激发用户的音乐创造力和探索欲
- 整体界面符合儿童审美，操作简单直观，游戏化体验流畅

## Non-Goals (Out of Scope)
- 不提供系统的乐理知识教学（如五线谱、音符时值计算等）
- 不提供课程进度管理、学习报告等复杂的教学管理功能
- 不支持多用户账号体系和数据云端同步
- 不包含唱歌/人声相关的训练功能
- 不提供移动端原生 App（仅 Web 端响应式适配）

## Background & Context
- 音乐启蒙教育对儿童智力发展和审美培养有重要意义
- 传统音乐学习门槛较高，需要专业老师和乐器，很多儿童难以接触
- 通过游戏化方式进行音乐感知训练，可以大幅降低学习门槛
- Web 端应用无需安装，易于在学校和家庭场景中推广使用
- 使用 Web Audio API 实现音频处理，无需依赖外部音频文件资源
- 使用 React + TypeScript 技术栈，保证代码质量和可维护性

## Functional Requirements

### FR-1: 高低音辨别游戏
- 系统播放两个或多个音符，用户判断哪个音更高/更低
- 支持多种难度模式：2 个音对比、3 个音排序、音程识别
- 每轮游戏包含 10 道题，完成后显示得分和正确率
- 提供即时反馈：答对显示绿色鼓励动画，答错显示正确答案
- 游戏难度可由用户自主选择

### FR-2: 节奏模仿游戏
- 系统播放一段节奏型（鼓点/拍手声），并显示视觉节拍提示
- 用户通过点击/敲击屏幕（或按键）来模仿节奏
- 实时检测用户敲击的时间点，与标准节奏对比
- 每次敲击给出即时反馈（完美/不错/太早/太晚）
- 一轮结束后显示整体准确度评分和星级评价
- 提供多种节奏型难度，从简单到复杂

### FR-3: 乐器音色识别游戏
- 系统播放某一乐器的单音或短句旋律
- 用户从 4 个乐器图标中选择正确的乐器
- 包含至少 6 种常见乐器：钢琴、小提琴、吉他、鼓、笛子、小号
- 每轮 10 题，随机出题，记录正确率
- 提供乐器图鉴功能，可单独试听每种乐器的声音

### FR-4: 力度强弱可视化探索
- 展示强(f)、中(mf)、弱(p)三种力度等级的概念
- 通过波形可视化：力度越强，波形振幅越大
- 通过粒子效果：力度越强，粒子数量越多、飞得越高
- 用户可通过滑块或按钮切换不同力度，直观感受差异
- 同时播放对应力度的音符声音，视听结合加深理解

### FR-5: 虚拟乐器自由探索
- 提供虚拟钢琴：至少两个八度的琴键，可点击或键盘演奏
- 提供虚拟鼓垫：至少 6 种鼓音色（底鼓、军鼓、踩镲、嗵鼓、叮叮镲、牛铃）
- 支持同时触发多个音（和弦）
- 界面简洁直观，适合儿童操作
- 音色使用 Web Audio API 合成或采样

### FR-6: 应用整体框架
- 首页展示 5 个功能模块的入口，图标化设计
- 每个模块可独立进入和退出
- 整体采用明亮、活泼的配色方案，符合儿童审美
- 响应式设计，适配桌面端和平板设备
- 所有操作有明确的视觉反馈和音效反馈

## Non-Functional Requirements

### NFR-1: 性能要求
- 页面首次加载时间 < 3 秒
- 音频播放延迟 < 50ms
- 节奏检测响应时间 < 100ms
- 动画帧率保持在 60fps 左右，不低于 30fps

### NFR-2: 可用性要求
- 所有功能操作步骤不超过 3 步
- 界面文字简洁，配合图标说明，适合 7-12 岁儿童理解
- 提供清晰的操作指引和帮助说明
- 支持鼠标/触屏两种操作方式

### NFR-3: 兼容性要求
- 支持 Chrome、Firefox、Safari、Edge 主流浏览器最新两个版本
- 桌面端和平板设备响应式适配
- 不依赖外部音频文件，全部使用 Web Audio API 合成或内置资源

### NFR-4: 可维护性要求
- 代码使用 TypeScript 编写，类型定义完整
- 组件化设计，模块化清晰
- 关键逻辑有单元测试覆盖

## Constraints
- **Technical**: Web 应用，React + TypeScript 技术栈，使用 Web Audio API 处理音频
- **Business**: 纯前端应用，无后端服务，数据存储在浏览器本地
- **Dependencies**: 
  - React 18 + TypeScript
  - Web Audio API（浏览器原生）
  - 可选：动画库（如 framer-motion）
  - 可选：状态管理（如 Zustand）

## Assumptions
- 用户设备支持 Web Audio API（现代浏览器均支持）
- 用户设备有音频输出设备（扬声器/耳机）
- 节奏游戏使用鼠标点击或触屏敲击作为输入方式
- 虚拟钢琴可以通过鼠标点击或电脑键盘演奏
- 所有音频使用 Web Audio API 合成，无需加载外部音频文件

## Acceptance Criteria

### AC-1: 高低音辨别游戏可正常游玩
- **Given**: 用户进入高低音辨别游戏，选择难度
- **When**: 系统播放音符，用户点击选择答案
- **Then**: 系统即时反馈对错，记录得分，完成 10 题后显示最终成绩
- **Verification**: `programmatic`
- **Notes**: 需验证音频播放正常、答案判断正确、计分准确

### AC-2: 节奏模仿游戏检测准确
- **Given**: 用户进入节奏模仿游戏，选择节奏型
- **When**: 系统播放节奏后，用户跟随节拍敲击
- **Then**: 系统实时反馈每次敲击的准确度，结束后显示总体评分
- **Verification**: `programmatic`
- **Notes**: 需验证时间检测精度在 ±100ms 以内，反馈及时

### AC-3: 乐器识别游戏正常运行
- **Given**: 用户进入乐器猜猜看游戏
- **When**: 系统播放乐器声音，用户点击选择乐器图标
- **Then**: 系统判断对错，记录正确率，完成后显示成绩
- **Verification**: `programmatic`
- **Notes**: 需验证至少 6 种乐器音色有明显区分度

### AC-4: 力度强弱可视化效果直观
- **Given**: 用户进入强弱探索模块
- **When**: 用户切换不同力度等级（f/mf/p）
- **Then**: 波形振幅和粒子效果同步变化，同时播放对应力度的声音
- **Verification**: `human-judgment`
- **Notes**: 需验证视觉效果能直观体现力度差异，视听同步

### AC-5: 虚拟乐器可正常演奏
- **Given**: 用户进入虚拟乐器模块（钢琴/鼓垫）
- **When**: 用户点击琴键/鼓垫或使用键盘
- **Then**: 即时发出对应音色的声音，界面有按键反馈
- **Verification**: `programmatic`
- **Notes**: 需验证响应延迟 < 100ms，支持多键同时按下

### AC-6: 整体界面符合儿童审美
- **Given**: 用户打开应用首页
- **When**: 用户浏览各个功能模块
- **Then**: 界面色彩明亮活泼，图标清晰可爱，操作直观简单
- **Verification**: `human-judgment`
- **Notes**: 配色使用明亮的糖果色，避免过于复杂的设计

### AC-7: 响应式适配正常
- **Given**: 用户在不同尺寸设备上打开应用
- **When**: 在桌面端（>1024px）和平板端（768-1024px）浏览
- **Then**: 界面布局自适应，所有功能可正常使用
- **Verification**: `human-judgment`
- **Notes**: 至少保证桌面端和平板端可用，手机端仅作基本适配

### AC-8: 应用性能达标
- **Given**: 用户首次访问应用
- **When**: 页面加载完成，开始使用各项功能
- **Then**: 首屏加载 < 3s，音频响应 < 100ms，动画流畅
- **Verification**: `programmatic`
- **Notes**: 使用 Chrome DevTools Performance 面板检测
